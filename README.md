# 物流倉庫の棚番一括変更RPAツール

## 概要

本プロジェクトは、物流倉庫の移転に伴う約12,000件の棚番マスタ変更に備えて開発した、PythonベースのRPA（業務自動化）ツールです。

システム部門へ一括処理プログラムの用意を依頼していましたが、倉庫移転という大規模なプロジェクトを滞りなく進めるため、万一に備えて複数の手段を確保しておく必要があると考えました。そこで、一括処理プログラムが利用できない場合にも棚番変更を進められるよう、基幹システムの画面操作を自動化するRPAを代替手段として開発・検証しました。

**最終的にはシステム部門が用意した一括処理プログラムを使用したため、本RPAによる本番の一括更新は実施していません。**

このリポジトリでは、開発の経緯、技術的な課題への対応、AIの活用方法、および公開用サンプルを紹介します。

## 開発背景と課題

倉庫移転に伴い、約12,000件の棚番マスタを変更する必要がありました。

システム部門へ一括更新を依頼していましたが、移転までに利用できるかが不透明だったため、次の課題に備える必要がありました。

1. 一括処理が利用できない場合、基幹システムの画面から大量のデータを更新する必要がある。
2. 手作業では多くの時間を要し、入力漏れや誤入力が発生するリスクがある。
3. 更新途中にエラーが発生した場合、処理済みの範囲と中断箇所を確認できる仕組みが必要になる。

そこで、Excelからのデータ読み込み、画面操作、エラー検知、処理結果の記録を組み合わせたRPAを、万一に備えた代替手段として準備しました。

## 想定していた効果

当時の試算では、手作業で約12時間かかる見込みの作業に対し、RPAを夜間に実行することで、人が作業に関与する時間を約90分に抑えることを想定していました。

人の作業時間を比較すると、約87.5％、概算で約88％の削減に相当します。

**これらは本番運用で測定した実績ではなく、開発時点での想定・試算です。また、人が関与する時間とRPA全体の実行時間は異なります。**

## 開発版と公開用サンプルの違い

開発版は、基幹システムの画面を操作し、棚番マスタを更新するために作成したRPAです。実際の更新には、対象の基幹システムと、その操作環境が必要です。

公開用サンプルでは、機密情報保護のため、基幹システムへの自動操作をコンソール出力と模擬処理に置き換えています。

**公開用サンプルは基幹システムへ接続せず、実際の棚番マスタも更新しません。**

また、開発版で取り組んだ13件単位のバッチ処理、画面状態の検知、複数の入力方法の切り替え、重複データへの対応など、すべての機能を再現したものではありません。

## 開発版で取り組んだ主な機能

- **操作用GUI**：倉庫コードの入力と処理開始を行う画面を作成。
- **Excel連携**：品目コードと新しい棚番をExcelから読み込む処理を実装。
- **バッチ処理**：対象画面の入力件数制限に合わせ、13件単位で処理。
- **画面状態に応じた待機**：入力欄が操作可能になるまで待ち、次の操作へ進む処理を導入。
- **エラー検知と中断**：基幹システム側の警告ダイアログを検知し、異常時に処理を中断する仕組みを実装。
- **処理結果の記録**：処理結果、詳細メッセージ、記録日時をExcelへ書き込む機能を追加。

詳しい開発経緯は、[development_history.md](development_history.md)を参照してください。

## 公開用サンプルの動作

1. 操作用GUIで倉庫コードを入力し、「スタート」を押します。
2. `input_sample.xlsx`のアクティブシートを読み込みます。
3. 2行目以降の品目コードと新棚番を順番に読み込みます。
4. 更新操作の代わりに、処理内容をコンソールへ出力します。
5. 模擬処理の結果を、入力ExcelファイルのC～E列へ記録します。

### Excelの列構成

| 列 | 内容 |
| --- | --- |
| A列 | 品目コード |
| B列 | 新棚番 |
| C列 | 模擬処理の結果 |
| D列 | 詳細メッセージ |
| E列 | 記録日時 |

A列に値がない行はスキップします。

品目コードに大文字の`ERROR`を含めると、模擬エラーとして処理を中断します。これはエラー時の動きを示すための条件であり、実システムのエラーを検知しているわけではありません。

入力した倉庫コードはコンソールへの表示に使用し、実システムへの接続には使用しません。

## 公開用サンプルの実行方法

### 必要な環境

- Python
- Tkinterを利用できる環境
- `openpyxl`

公開用サンプルでは、`pyautogui`、`pywinauto`、`pandas`は使用していません。

### 準備と実行

1. `tanaban_rpa_sample.py`と`input_sample.xlsx`を同じフォルダーに配置します。
2. 入力Excelファイルのコピーを保存します。
3. Excelファイルを閉じます。
4. 必要なライブラリをインストールします。

```bash
python -m pip install openpyxl
```

5. ファイルを配置したフォルダーで、次のコマンドを実行します。

```bash
python tanaban_rpa_sample.py
```

現行コードは、実行時のカレントディレクトリから`input_sample.xlsx`を探します。

**処理結果は入力Excelファイルへ上書き保存されます。試す際は、必ずコピーを使用してください。**

### 現行サンプルの既知の制約

- 模擬エラーで中断した後にも、正常終了メッセージが表示される問題があります。
- 新棚番の空欄、データ形式、重複などの入力検証は実装していません。
- 通常の処理結果はループ終了後にまとめて保存するため、予期しない例外や終了操作によって、未保存の結果が失われる可能性があります。
- 再実行時に前回の結果を消去しないため、今回処理していない行に古い記録が残る場合があります。

これらは公開用サンプルの制約です。

開発者は、現場の操作手順と要件を整理し、実際の画面で動作を確認しながら、提案されたコードの採否や改善内容を判断しました。

## この開発で得られた知見

- 現場の作業手順を整理し、自動化する範囲を定めること
- GUI自動操作で、画面の応答や入力可能な状態を確認すること
- 異常時に処理を中断し、処理結果を記録すること
- AIが生成したコードを、実際の環境で検証しながら改善すること
- 正式な対応と並行して、万一に備えた代替手段を準備すること

本RPAによる本番の一括更新は行いませんでしたが、倉庫移転に向けて代替手段を準備し、開発・検証を通じて自動化に関する知見を得ました。
